# Objects should be upcastable to supertraits

## Prologue
In Rust, trait objects representing subtraits cannot be coerced to trait objects for their supertraits. The compiler rejects casts like `s2 as @T` when `s2` is already a trait object, preventing natural use of trait inheritance in dynamic contexts. Users resort to unsafe workarounds or manual vtable manipulation. Without built-in support, ergonomic patterns that rely on upcasting (e.g., passing a subtrait object to a function expecting a supertrait object) remain impossible.

## Discussion
The issue was broadened from a single-trait identity cast to the general need for subtrait-to-supertrait upcasting. The core challenge is that vtables are distinct and a coercion must replace the vtable to point to the embedded supertrait vtable, as noted by bblum and nikomatsakis. The conversion is a coercion, not subtyping, because a representation change is required.

An implementation strategy was outlined: store supertrait vtables adjacent to subtrait vtables in a recursive layout so that upcasting uses a statically known offset. This duplicates supertrait vtables in diamond inheritance but provides constant-time upcasting. Alternative offset-based approaches were considered slower.

RFC 250 (postponed) proposed upcasting with embedded vtables. RFC 401 established that such conversions should be implicit unsizing coercions, and RFC 982 defined DST coercion rules. The lang team initially misread the request but later confirmed subtrait-to-supertrait casting was still missing. Users provided workarounds (transmute, manual safe wrappers, compiler-internal hacks) and use cases showing limitations in generic code and trait interop. The current tracking issue is rust-lang/rust#65991.

## Solution
Implement implicit coercion from a reference to a subtrait object (`&dyn Subtrait`) to a reference to a supertrait object (`&dyn Supertrait`) where `Subtrait: Supertrait`. The coercion is part of the unsizing coercion rules and adjusts the vtable pointer to the embedded supertrait vtable within the subtrait vtable. This feature was developed in nightly and is scheduled for stabilization in Rust 1.86, as stated in PR #134367.

## Consequences
- Ergonomic upcasting from subtrait objects to supertrait objects becomes possible without unsafe code or manual coercion.
- The binary size may increase due to duplicated supertrait vtables in diamond inheritance under the embedding strategy.
- Upcast cost is O(1) using the predefined vtable offset.
- [Inferred] Code that previously relied on transmute or manual vtable offsetting can be simplified.
- Future multi-trait object support (`&(Foo + Bar)`) can extend the same vtable embedding or multi-vtable layout.
