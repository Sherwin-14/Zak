# Move or fork to independent organization

## Status
Accepted

## Date
2026-04-14

## Deciders
Earthaccess steering committee

## Context and Problem Statement
The Earthaccess project is community-owned but hosted under the NSIDC GitHub organization, which does not reflect its community ownership model. The community sought to move the repository to a more independent location to insulate from potential organizational directives, enable more flexible contributor management, and bring related efforts under a single organization. Without this change, the project could remain subject to influences that are not community-driven, and the ability to group related tools (e.g., python_cmr) under consistent development practices would be limited.

## Decision Drivers
- Preserve the repository’s history, issues, and discussions.
- Enable automatic redirects from the old location to avoid disruption.
- Minimize community disruption and transitional effort.
- Allow grouping of related projects under a common organization for unified development practices and documentation.
- Maintain the ability for NASA to contribute without owning the community resources.
- Avoid loss of the project’s name and existing identity.

## Considered Options
- Move (transfer) the repository to a new independent GitHub organization.
- Fork the repository to a new independent GitHub organization.

## Decision Outcome
The Earthaccess repository was transferred to the `earthaccess-dev` GitHub organization. The transfer was chosen over forking because it preserves issues, discussions, and adds automatic redirects, reducing community disruption and avoiding the significant transitional effort a fork would require.

## Consequences
- Repository history, issues, and discussions are preserved.
- Redirects from the old NSIDC location automatically point to the new organization, minimizing broken links for users.
- The community avoids the extensive work and cost associated with re-establishing the project under a new name or repository.
- The new organization enables grouping related tools (e.g., python_cmr) under consistent development practices and a unified documentation site.
- The project name “earthaccess” is not a NASA brand, which reduces the risk of ownership disputes.
- Coordination with NSIDC is required to authorize the transfer, which may affect future funding opportunities.
- [Inferred] Future decisions about contributor permissions and project governance can be made more independently within the new org.

## Pros and Cons of the Options

### Move (transfer)
- **Pros:**
  - Keeps the full commit history, issue tracker, and discussions intact.
  - GitHub automatically adds redirects from the old location, so existing links continue to work.
  - Minimal disruption for users and contributors.
  - Avoids fragmenting the community or duplicating documentation.
  - Enables easy coexistence with other projects in a shared org.
- **Cons:**
  - Requires buy-in and cooperation from NSIDC to authorize the transfer.
  - Potential risk of name disputes, though mitigated because “earthaccess” is not a NASA trademark.

### Fork
- **Pros:**
  - Provides a clean break from the existing organization without needing approval.
  - Allows a name change if desired.
- **Cons:**
  - Does not retain issues, discussions, or redirects, leading to broken links and lost institutional memory.
  - Would be highly disruptive to the community and require substantial effort to regain the project’s current standing.
  - Risks fragmenting the user base and development effort.
