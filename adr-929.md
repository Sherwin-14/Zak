# pretty-printer loses parens in "if (1 == fail) { }"

## Issue
The Rust pretty-printer discarded parentheses around `if` discriminants, turning `if (1 == fail) { }` and `if 1 == (fail) { }` into `if 1 == fail { }`, which fails to parse. The output was syntactically invalid, and a fix was needed to preserve parentheses as in the original source.

## Decision
Implement parenthesization of the entire discriminant in the pretty-printer by making `print_maybe_parens_discrim` recurse on the rightmost expression. The fix was later realized using paren nodes.

## Positions
The issue reporter proposed that `print_maybe_parens_discrim` should recurse on the rightmost expression to wrap the whole discriminant. @brson agreed with this approach.

## Argument
The reporter argued that parenthesizing the entire discriminant (the first of three possible solutions) would resolve the syntactic ambiguity effectively and could be implemented cleanly. @brson concurred without additional counter-arguments.

## Implications
The fix ensures that the pretty-printer correctly parenthesizes if-condition expressions, producing parseable output. It eliminates the class of errors where necessary parentheses were dropped.
